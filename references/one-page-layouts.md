# One-page layouts

Choose from the information relationship. The one-page view is responsive HTML, not a generated text-heavy bitmap.

| Layout | Use when | Dominant relationship |
|---|---|---|
| `bento-grid` | Several equally important takeaways | Modular grouping |
| `dashboard` | Metrics and status dominate | Monitoring and comparison |
| `comparison-matrix` | Multiple options share criteria | Cross-axis comparison |
| `linear-progression` | Work advances through ordered stages | Sequence |
| `timeline` | Dates and evolution matter | Chronology |
| `hub-spoke` | One core concept connects to dimensions | Central dependency |
| `hierarchical-layers` | Concepts contain sub-levels | Hierarchy |
| `funnel` | Inputs narrow toward an outcome | Filtering |
| `iceberg` | Visible effects hide deeper causes | Surface versus depth |
| `tree-branching` | One origin produces alternatives | Branching |
| `circular-flow` | The process repeats | Feedback loop |
| `winding-roadmap` | Progress includes detours and milestones | Journey |
| `bridge` | A mechanism connects problem and outcome | Transition |
| `story-mountain` | Tension rises to a turning point | Narrative arc |
| `structural-breakdown` | A system must be decomposed | Part-to-whole |
| `binary-comparison` | Two alternatives dominate | Side-by-side contrast |
| `periodic-table` | Many small items belong to categories | Taxonomy |
| `dense-modules` | Expert audiences need high information density | Compact reference |

## Selection rules

- Prefer `linear-progression` or `timeline` when order changes meaning.
- Prefer `comparison-matrix` only when comparable criteria are explicit.
- Prefer `dashboard` when at least three meaningful metrics exist.
- Prefer `structural-breakdown` for architectures and mechanisms.
- Avoid `bento-grid` as a default when a stronger relationship exists.
- On mobile, every layout must collapse to one readable column without changing fact order.
